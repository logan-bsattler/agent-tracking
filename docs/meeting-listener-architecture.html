Meeting listener

Three separate stages, and only the middle one uses a model. A Python process reads Teams captions off the screen into transcript files. A dedicated Claude session reads those files in batches, writes notes and proposes intents. Client agents read the notes through coord_meeting_notes.

What each stage does

1 · Capture

coord_mcp/captions.py · auto

  • Teams has no live-transcript API, so it reads the captions pane through UI Automation. Windows Live Captions is a fallback without speaker names.
  • TeamsDiffer and teams_entries decide what text is new and wait 4 s for a caption to settle. This logic is unit-tested; reading the screen only fetches text.
  • Auto starts a transcript when captions show (unless the title matches skip.txt). It ends on window close or 60 s without captions. A generic title like "Microsoft Teams" never splits a meeting.
  • Started at logon by a Startup .lnk. Stops when auto.stop exists.

2 · Delivery

captions watch --follow, run by Monitor

  • Batcher sends lines after 20 s of quiet, or once the oldest has waited 90 s. Every batch is a model turn.
  • Saves its place in <transcript>.watch, so a re-armed Monitor (30 min max) sends nothing twice.
  • follow tracks the newest transcript and replays meetings nobody watched (missed()).

3 · Interpretation

examples/meeting/CLAUDE.md

  • Separate session with only coord_propose_intent and coord_board_summary. Lives outside C:\development\agents so it doesn't inherit Master's CLAUDE.md.
  • Notes: decisions and reasons, constraints, owners, open questions, with line numbers.
  • One intent per request, commitment, scope change or blocker. Checks ## Proposed first so it doesn't propose the same item twice.

4 · Downstream

coord_mcp/notes.py, coord_mcp/meetings.py

  • coord_meeting_notes decides which client a meeting belongs to: the notes' client: line, then the calendar meeting running when captions started, then a subject rule.
  • Meetings with no client are visible to Master only. Internal meetings stay internal.
  • The calendar import also drives meeting-hours tracking, separate from transcripts.

Known gaps (as of 2026-10-26)

Logon start unproven

  • The .lnk replaced a blocked .cmd, but hadn't yet been seen to start at a real logon.

Dashboard has no logon start

  • Port 8765 has to be restarted by hand after a reboot.
