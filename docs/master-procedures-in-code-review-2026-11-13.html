Review findings

Fixed: client-visible SharePoint note carried the agent's summary fixed in 95282f9

Rec 4 appended the result's free-text summary to every code-change note. SharePoint is what clients see, and a summary is written for master, so internal wording ("Ben still needs to chase the client") could have reached the client. The note is now only what the manual asks for: the date, what landed, and its name or CVC/ticket. The ticket is still read from the summary. A test covers it.

Fixed: rec 4's tests depended on rec 2 fixed in 95282f9

The promotion test relied on complete_task creating the review, which only rec 2 does. The code itself had no such dependency. The helper now creates the review when there isn't one, so each change merged and tested on its own.

Fixed: stale labels in decision text fixed in 076c6ae

Auto-close decisions said "(rec 3)" and pipeline-note decisions said "(rec D)". Neither matched the numbering used here, and both would have shown on the board.

Accepted: master's own sends are invisible to auto-dispatch watch

If master sends a task and the client session is busy with something that isn't a board task, code can send the same Do task X line again after 2 minutes. That's a duplicate message, not lost work.

Accepted: a lapsed lease can duplicate a SharePoint note watch

If add_task_note succeeds but the report back to the board fails, the 2-minute lease lapses and the same note is offered again. The client would see a duplicate. This is unlikely, since the call takes seconds.

Accepted: auto-created reviews quiet "result unread" for deliverables watch

The minder treats a child task as master acting on a result. The new open review still surfaces through "never delivered" or auto-dispatch, so master is still woken, just under a different item.

Policy check: rec 1 matches the manual

The manual says an id-match close is enough on its own. Topic-match, any intent naming commitments, and any unknown or already-closed loose-end id all stay with master. Each intent is closed in its own savepoint, so one failure doesn't block the rest.
