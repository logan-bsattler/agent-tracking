Performance review: Claude and coord on this machine

2026-11-19, measured 11:57–12:08 plus timings on a snapshot of ~/.coord/coord.db taken at 12:01. No code changed.

The coord dashboard is the main CPU problem, and one fix takes about 90% of it away. Each master session's console tick (every 10 s) calls /api/parked, which takes 13–15 s, and /api/dispatch/claim, which takes 5–7 s. The ingest loop's minder_check adds 21 s every pass. Both master sessions tick, and ticks overlap because the mod does not wait for the previous one to finish, so the dashboard asks for about 4 cores of work and gets 2–4. That matches the 2–4 cores seen this morning, and it is also what holds the write lock for minutes.

Almost all of that time is direct.chain. Commit 9d74834 (branch claude/magical-morse-047d02, not on main yet) cuts /api/parked to 1.5 s, minder_check to 3.8 s and the claim to 0.6 s. Next steps: merge it, cache the minder's owed list so /api/parked costs milliseconds, and stop ticks from overlapping.

Memory is the second problem, and coord is not the cause. There is 15.5 GB of RAM and 0.9 GB was free. Each Claude Code session holds about 520–690 MB of private memory, the desktop app about 2.1 GB, and the Logan_Client Hyper-V VM 4.1 GB and about 1 core. The coord MCP servers are small: about 35 MB and 0 CPU each.

Why it piles up. $.clock.every(10_000, …) fires a new async tick every 10 s whether or not the last one has finished. When /api/parked plus the claim take about 20 s, each session keeps about two ticks in flight. ThreadingHTTPServer starts a thread for every request, and sqlite releases the GIL, so the work runs on several cores at once. Every request holds a read snapshot, and the claim's reads ran inside BEGIN IMMEDIATE before 528e728. That is how the dashboard became both the CPU hog and the long lock holder.

Self-inflicted I/O. ~/.coord/lock-holders.log (the d544a45 watchdog) is 87.7 MB after one morning and has no size cap. Pytest runs write to it too, because tests/test_health.py stacks appear in it. dashboard-errors.log is capped at 2 MB. coord.db is 60 MB, and four backups in ~/.coord add about 158 MB.
