Ranked fixes

Ranked by how many of the audited Ben items each would have kept off his desk. Counts do not add up across fixes beyond the class they target. None has been applied.

  1. Give client agents a 'who: Ben' test in their CLAUDE.md step 3, and enforce it in coord_complete_task — 144 items.
    Client CLAUDE.md files tell agents to put "every next step and open question" in follow_ups with who = a client key, Master, Ben or a person, and give no test for when Ben is right. Add: Ben only for send/approve/scope/access/judgement; a read, query, test, edit or draft is done in the same task or handed to the client's own key; a question for a client person is a draft the agent writes (draft_reply), never "ask X" for Ben. In code, replace the conservative regex in queue.route_for with the inverse default: a Ben follow-up must carry a reason tag (send | approve | scope | access | judgement) or it routes to the client.
  2. Refuse a Ben follow-up that repeats an open one (dedupe at completion) — 65 items.
    coord_complete_task inserts follow_ups as given; check_grouped compares items only within one result. Compare each new Ben item against that client's open Ben queue (queue.same_shape) and refuse or fold it, naming the existing id.
  3. Close Ben items when their task is revised, folded or overtaken (supersede on revision) — 60 items.
    Revisions (-r2, -r3, a re-run, a fold) open new Ben loose ends but leave the old ones open; the 14-day expiry in queue.py then only defers them, so they pile up in Deferred. When a task gets a child or a revision that covers the same item, or a decision folds it, close the parent's Ben items in the same call (dropped, citing the decision). Run it once as a dry-run sweep over the queue.
  4. Widen the workbook rule across results, not just within one — 47 items.
    check_grouped refuses three or more same-shape rulings in ONE result. Analysis runs that hand back one or two rows each, over several tasks, still land row by row. Count same-shape items across the client's open queue for the last 7 days, and make the MAG analysis specs say 'one workbook, one item' up front.
  5. Let master apply its own 'Deciding for Ben' rule in code at landing, and stop holding work behind Ben — 42 items.
    Master's CLAUDE.md lists four cases master decides (earlier ruling implies it; uncalibrated rate; duplicate; reversible with a clear default), but nothing checks them when a result lands, and the precedent matcher only compares loose-end text (3 of 685 matched). Match new Ben items against decisions on the same task and client (not only past loose ends), and have master record 'master default; Ben may override' instead of presenting. The same rule should end hold decisions: proceed on the default and let Ben override.
  6. Turn hold decisions into working defaults — 158 hold or defer decisions that name Ben still point at open work (94 wait on a ruling, 35 on an action of his); 71 of them say "master default" in their own reason, so master had a default and held anyway. Example: 70dab9ac6902 held a Royal #231 reply to John Polich until Ben rules round 3 on de116958d1cb. Rule: a hold behind Ben is allowed only for outward-facing work that turns on his answer; everything else proceeds on the default and Ben overrides. A client waiting on a reply gets the reply with the default, not a hold (as the target-date rule already says for dates).

Classes: root cause and examples

a. Agent work misrouted to Ben — 144

Subtypes: draft 98, edit 25, read 20, reconcile 1.

  • Client CLAUDE.md step 3 (MAG, LNK and the others share it): "put every next step and open question in follow_ups as {who, what}" with Ben as an allowed who and no test for when. Agents default to Ben for anything that touches a person, a server they cannot reach, or a question.
  • queue.route_for is deliberately conservative: any of ~30 person words (confirm, decide, ask, approve, send, call, scope, estimate, manual, VM, WebUI, "with Name") keeps an item on Ben, and only items that open with a read/run verb move. Of the 770 Ben items audited it would route 2.
  • Asks for a client person ("Ask QAD...", "Get X from Rajesh", "Confirm with Ari") are handed to Ben as a chore rather than drafted: "Agent work never reaches his queue" names replies, but not outbound questions.

Method and limits

  • Source: the dashboard's /queue page (685 open Ben loose ends with ids) and the /board Deferred lane (446 of the 447 deferred; one did not parse). Deferred items carry no loose-end id on that page, so they are keyed D-<task>-n in the workbook. Direct database reads are blocked by the coord guard.
  • Evidence per item: decisions recorded on its task (or naming it) after it was raised, from coord_get_decisions; near-duplicates by word overlap within a client.
  • Classification by five reviewer agents against one rubric (the brief's classes, first fit in the order c, e, b, d, a, f). It is judgement, so each row carries its reason for Ben to confirm or override in the workbook's Confirm column.
  • Not classified: 0 items.
